video-analysis リポジトリ構成

作業動画が宣言的 SOP（手順書）通りかを、ローカル小型 VLM（Qwen3-VL / Apple Silicon）で判定するシステム。ルート層は Web UI + サーバ、コア層は CLI ライブラリ。

ブラウザ

Web レイヤー (ルート)

ブラウザからリアルタイムでフレームを VLM に送り、観察結果を再生・確認する。

replay.html server.py vlm_backend.py

起動: ./run.sh → http://127.0.0.1:8765/replay.html

CLI

コアライブラリ

動画からフレーム抽出 → VLM 観察 → ルールベース判定を一括または個別実行。

extract observe judge cli

一括: python src/cli.py run --sop ... --video ...

アーキテクチャ・データフロー

実線: CLI パイプライン (run) / 青線: Web パス / 破線: backend → observe 合流

SOP 判定フェーズ

フェーズモジュール内容
Phase 0正解確認人間が動画を見て手順を確定
Phase 1observeVLM が各フレームに yes/no で回答
Phase 2judgeルールベースで PASS/FAIL 判定 (VLM 不使用)

VLM 実行モード

モード説明
vlmローカル Qwen3-VL (Apple Silicon)
mock全回答 no のスタブ
proxyVLM_UPSTREAM_URL へ転送

HTTP API

エンドポイント役割説明
GET /replay.html静的 UISOP 点検ビューア
GET /api/status状態確認VLM モード・ready 状態
POST /api/warmup事前ロードQwen3-VL をバックグラウンド読込
POST /api/vlm/analyzeフレーム分析image + questions → answers
POST /api/judgeSOP 判定sop_def + frames → verdict/events

環境変数

変数デフォルト説明
PORT8765HTTP サーバポート
VLM_MODEL4b2b | 4b (Qwen3-VL サイズ)
VLM_USE_MOCK(未設定)1 で全回答 no のモック
VLM_UPSTREAM_URL(未設定)外部 VLM プロキシ先 URL
VLM_SRC(自動)small_vlm_video_analysis/src パス
SOP YAML 構造: 1ファイルに 3 セクション — questions（VLM への質問）→ events（検出条件）→ relations（時間的関係: before / overlaps / not）。 observe が questions を処理し、judge が events と relations を機械的に評価する。
